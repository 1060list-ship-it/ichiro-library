# 要約保存切替手順

本書は保存側の切替準備。校閲consumer・公式照合・候補抽出LLM・新UIは対象外。各本番操作は一幾の承認を待つ。資格認証の回復はownerが行い、トークン値は要求・参照しない。

1. 手動起動を含む旧writerをすべて洗い出し、停止と実行中処理の終了を確認する。停止操作は承認後に実施する。
2. バックアップの取得と復旧可能性を確認する。取得・復旧確認は承認後に実施する。
3. 037と新保存側を整合する組で反映する。途中はwriter停止を維持する。037の適用は単回を前提とし、部分適用へ再実行しない。
4. 保存経路とDB状態を検証する。確認済み行、初成功時の単一pending run、履歴不明行、再保存時のstale化を確認する。
5. 初成功pendingを消費する機構は未実装。これと校閲全体の準備・検証を本番再開の残条件とし、一幾の承認後にのみ再開する。

037適用後は旧writerへの単純rollbackは不可。問題時は停止を維持し、互換性のある新コードによる復旧かバックアップからの復旧をownerが判断する。

| 観点 | 確認 |
| --- | --- |
| 停止 | 全旧writer・手動起動・実行中処理 |
| 復旧 | バックアップと復旧可能性 |
| 適用順 | 停止中に037と新保存側を整合反映 |
| 既存行 | 確認済み保護、履歴不明は人手確認 |
| 初成功 | 本文とpending runを原子的に保存 |
| 再保存 | 旧active runをstaleにする |
| 再開 | consumer等の残条件、検証、一幾承認 |
