# ichiro-library 公開サイト redesign デザインスペック

> 作成日: 2026-09-30  
> 対象: `apps/web/src` の公開画面のみ（`/admin` は対象外）  
> 実装担当: paz  
> 前提: このサイトはYouTubeへの入口である。検索・要約・チャプターは「観る理由」を渡すためにあり、サイト内で視聴を完結させない。

## 0. 目的・完了条件

### 目的

夜に「どの配信だったか」を探しているファンが、情報の山に沈まず、気になる一本を見つけてYouTubeへ迷わず移れる状態にする。

### 完了条件

- 一覧カードだけで、配信の題材・時期・見どころ・YouTubeへ行く行動が一目で分かる。
- 要約本文を一覧で読ませない。カードは冒頭**110文字**まで、続きを読みたい人だけ詳細へ進ませる。
- 公開ページ全体が同じ「夜のアーカイブ」トーンで揃い、検索・期間・タグ/コーナー・マガジン・既存の詳細導線を失わない。
- モバイル幅360pxから横スクロールや極端な圧縮なしで読め、主操作のタップ領域は最低44pxある。

## 1. デザインコンセプト

**夜の深い水面から、観たい一夜を拾い上げるアーカイブ。**  
情報は静かに整理し、サムネイルと一文の見どころで感情を動かす。  
行き先は常にYouTube。ここは視聴の代わりではなく、再生ボタンを押す前の確信をつくる場所だ。

### 配色

ベタなダークグレーと青の組み合わせはやめる。黒ではなく、わずかに海の色を持つ濃紺を基調にする。YouTubeへ出る行動だけを暖色で強くする。

| 役割 | トークン名 | 値 | 用途 |
|---|---|---:|---|
| 背景 | `--canvas` | `#08111D` | ページ全体。真っ黒にせず目を休ませる。 |
| 面 | `--surface` | `#101E2D` | カード、検索欄、ドロワー。 |
| 面・浮き | `--surface-raised` | `#16283A` | hover、選択状態以外の操作面。 |
| 線 | `--line` | `#294056` | カード境界、区切り。白線を使わない。 |
| 本文 | `--ink` | `#E8EEF5` | 見出し、本文。 |
| 補助本文 | `--muted` | `#9EAFBF` | 日付、件数、説明。コントラストを落としすぎない。 |
| 探索のアクセント | `--aqua` | `#7EE3D0` | フォーカス、選択フィルタ、時刻リンク。 |
| YouTube CTA | `--signal` | `#FF695C` | 「YouTubeで開く」だけ。通知色・タグ色には流用しない。 |

- 背景には`radial-gradient`を一層だけ使ってよい（左上にごく弱い青緑、透明へ）。写真・魚・波の装飾を足さない。音楽の世界観を小道具で説明すると安っぽくなる。
- hoverは「明るくする」より、境界線を`--aqua`寄りにしサムネイルを`scale(1.015)`する。モーションは150〜200ms、`prefers-reduced-motion`では無効化する。
- YouTubeのブランド赤を真似た小さなアイコンだけにしない。`--signal`の塗りボタンに「YouTubeで開く ↗」と文字で出す。どこへ行くかを隠すな。

### タイポグラフィ

- 新規npm依存は追加しない。`next/font`も今回必須ではない。`Geist`を英数字・UI補助に使い、日本語本文は`"Hiragino Sans"`, `"Yu Gothic"`, `system-ui`, `sans-serif`の順でフォールバックする。現状の`Arial`固定は外す。
- ページ見出し: `text-2xl`（mobile）/ `text-4xl`（sm以上）、`font-semibold`、`tracking-[-0.02em]`。カード見出し: `text-base`、`font-semibold`、2行まで。
- 本文: `text-sm`、`leading-7`。メタ情報とタグ: `text-xs`、数値には`font-mono tabular-nums`を使う。
- 英大文字の追い込み・過剰な極細フォントは使わない。日本語の配信タイトルが主役だ。

### 余白・形

- コンテンツ幅は`max-w-6xl`。本文中心の詳細・マガジン本文は`max-w-3xl`。左右paddingは`px-4`（mobile）/`sm:px-6`。
- 8px基準で余白をそろえる。セクション間は48px（mobile）/64px（sm以上）、カード内は16px、要素間は8px。
- 角丸はカード・入力`rounded-2xl`、チップ`rounded-full`、画像はカード上辺に沿う。薄い境界線と面の差で階層をつくり、影を多用しない。

## 2. 情報設計と共通の操作原則

### ユーザーの一本道

```text
探したい言葉・時期を入れる
  → 一覧で「この回かも」を判断する
  → [YouTubeで開く] で視聴する
       └ 迷う時だけ [要点・チャプターを見る] で詳細を開き、時刻からYouTubeへ渡る
```

- 主アクションは常に外部YouTubeリンク、二次アクションはこのサイトの詳細。逆にしない。
- 外部リンクは`target="_blank" rel="noopener noreferrer"`を維持し、ラベル末尾に`↗`を付ける。新規タブであることが読めるようにする。
- 検索、あいまい検索、期間、タグ、コーナー、カテゴリの状態は現行URLクエリとロジックを維持する。見た目を替えるために検索契約を変えない。
- ローディング、0件、取得失敗の文言は背景に溶かさない。`--surface`の領域内に、次の行動（検索語の変更・フィルタ解除）を添える。

## 3. 画面別仕様

### 3-1. 共通ヘッダー / ナビゲーション

#### 構成

```text
[ ichiro library ]                         [配信一覧] [マガジン] [プレイリスト]
[ live archive / 山口一郎 YouTube配信 ]     （ログイン・管理は右端の補助操作）
```

- `PublicSiteHeader`を`sticky top-0 z-30`にする。背景は`--canvas/90`+`backdrop-blur`、下線は`--line`。スクロール中も「今どこにいるか」を消さない。
- ロゴは文字だけでよい。`ichiro`を`--ink`、`library`を`--aqua`にし、下に小さく`LIVE ARCHIVE`を置く。既成ロゴ画像は作らない。
- デスクトップはロゴ、主要ナビ、補助操作の3列。主要ナビ順は **配信一覧 / マガジン / プレイリスト**。管理・ログイン・ログアウトは情報の重みを下げた右端に置く。
- mobileはブランドを左、ログイン等を右上の小さな操作にし、主要ナビはヘッダー下の横スクロールしない3分割タブにする。タブ高は44px。アクティブは塗りつぶしでなく下線`2px --aqua`と本文色で示す。
- `/stream/*`、`/magazine/*`の個別ページでも独自の簡易ヘッダーを作らず、このヘッダーを使う。戻るリンクは本文先頭に置く。画面ごとにナビの見え方が変わると帰り道が消える。

### 3-2. トップ（配信一覧・検索・絞り込み）

#### ファーストビュー

```text
LIVE ARCHIVE                                      320 ARCHIVES
一郎の配信から、今夜観たい一回を探す。
人物・話題・日付から、あの配信へ戻れる。

[ 🔎 人物名・話題・日付で探す                         ]
[あいまい検索 ○]    例: ハマダ / 2024年3月 / 深夜 -ゲーム

[最近の配信] [再生数] [高評価率] [歌唱]   ← 横一列、現在地を明確に
期間 [全期間] [2026] [2025] ...
[絞り込む（タグ・コーナー） ▾]              ← 開くと既存チップを表示
```

- 現行の長い説明文をヒーローにしない。`h1`は上記のように「何ができるか」を一文で言い切る。件数と最終更新は右上の補助情報に下げる。
- 検索欄をヒーロー内の主役にする。高さ48px、検索アイコン、フォーカス時は`--aqua`の`2px`リング。placeholderは現行より短く「人物名・話題・日付で探す」。
- あいまい検索は検索欄直下に説明付きトグルとして残す。サンプルクエリはボタンらしいチップにし、最大3件。検索の使い方はアコーディオンのまま保持するが、検索欄から24px以上離さない。
- カテゴリ4件は同じ重さの丸ボタンではなく、タブにする。mobileで文字が潰れる場合は`text-xs`、ラベルを短縮しない。選択時は`border-b-2 border-[--aqua] text-[--ink]`。
- 年フィルタは常時見せる。タグとコーナーは初期状態では`絞り込む（タグ・コーナー）`にまとめ、開いた中で区分を明示する。機能を隠すためではない。320件を眺める人に、最初からチップの壁をぶつけないためだ。
- 選択済みの条件は検索欄の下に`「ハマダ」× 2024年 × 深夜`のようなチップで表示し、各チップに解除ボタンを付ける。全解除も表示する。今どんな結果なのかを推測させない。

#### 一覧セクション

- 見出しは`最近の配信`ではなく、状態に応じて現在の条件を読み上げる現行ロジックを維持する。見出し直下に`表示中 24件 / 全320件`を`tabular-nums`で置く。
- `grid-cols-1`（mobile）→`sm:grid-cols-2`→`lg:grid-cols-3`。現行`max-w-3xl`の2列を、一覧に限り`max-w-6xl`へ広げる。カード一枚に呼吸を与える。
- 1ページ内に一度に全件を無制限に見せる現状のデータ取得・表示件数は変更しない。ページネーション、無限スクロール、並び替え仕様の変更は今回しない。

### 3-3. トップ一覧カード（`StreamCard`）

#### 表示順と情報量

```text
┌─────────────────────────── thumbnail (16:9) ──────────────────────────┐
│  [2025.08.12]                                      [2時間18分]         │
│                                                          [YouTube ↗]  │
└──────────────────────────────────────────────────────────────────────┘
  コーナー / タグ（最大2個、残りは +N）
  配信タイトル（2行まで）
  2025.08.12  ・ 再生 123,456  ・ チャプター 18
  要約の冒頭110文字まで。気になるなら詳細へ。
  [YouTubeで開く ↗]                  [要点・チャプターを見る →]
```

- **要約は`SUMMARY_PREVIEW_LENGTH = 110`文字に制限する。** `stream.summary.slice(0, 110)`の末尾に`…`を付け、続きはカード下の`要点・チャプターを見る →`で`/stream/[video_id]`へ進む。CSSの`line-clamp`だけで隠さない。文字数がデータ量で変わると、カードの高さと情報設計が崩れる。
- タイトルをカード内の最重要情報にする。日付・再生数・コメント数をタイトルと同列に並べない。コメント数はカードから外し、必要なら詳細で補助情報として扱う。
- タグ/コーナーはタイトルの前に最大2つ（コーナー優先）だけ表示し、残りは`+N`。フィルタに使う既存のクリック機能は維持する。`+N`は閲覧専用でクリックさせない。
- 再生数はランキング表示時に順位と一緒に強調し、通常一覧では小さなメタ情報に留める。ランキングの1〜3位だけサムネイル左上に`01`等の大きめ数字を出し、金色の王冠のような装飾は使わない。
- サムネイルがない場合でもカードを壊さない。`--surface-raised`の16:9領域に`NO THUMBNAIL`と短いタイトルを出し、CTAは同じ位置に残す。

#### 操作

- サムネイル右下の半透明ボタンとカード最下部の主CTAは、ともに**YouTube直リンク**。前者はアイコン補助、後者は文字を伴う主操作とする。カード全体をリンクにしない。リンクとボタンを入れ子にすると、モバイルで意図しない遷移が起きる。
- 二次CTAの`要点・チャプターを見る →`だけが内部詳細へのリンク。44pxのタップ高を確保し、YouTube CTAと横並びにできない幅では縦積みにする。
- ブックマーク/プレイリスト追加はログイン利用者だけに今のまま出す。ただしYouTube CTAより派手にしない。カード下部の補助アクション群へまとめる。
- hover/focus時にはカード境界とYouTube CTAだけが反応する。サムネイル・タグ・本文すべてがクリックできるように見える状態を作らない。

### 3-4. 配信詳細（`/stream/[id]`）

#### レイアウト

```text
← 配信一覧に戻る

2025.08.12 / 2時間18分 / 再生 123,456
配信タイトル（h1）
[ YouTubeでこの配信を開く ↗ ]  ← 画面内で最初の主アクション

[ YouTube埋め込み（既存維持） ]
このページは配信を探すための案内です。続きはYouTubeで。

見どころ
AI要約（読みやすい段落。報告UIは本文から離す）

チャプター（各行: 時刻 / 題 / 1行の補助説明）  → YouTubeの該当時刻で開く

関連タグ・コーナー
[ YouTubeでこの配信を開く ↗ ]
```

- 既存iframeは機能維持のため残す。ただし詳細の主役にしない。タイトル直下に外部CTAを置き、iframeの直下にも「YouTubeで続きから見る ↗」を置く。autoplay・サイト内プレイリスト・視聴履歴など、完結視聴を強める機能は足さない。
- `h1`はmobileで`text-2xl`、`sm`以上`text-4xl`。日付・時間・再生数は1行のメタ情報にまとめる。タグ群は要約の後に置き、タイトルの前後に散らさない。
- AI要約は`見どころ`見出しの下で、`--surface`の面に16px padding、`leading-7`。全文を残す。要約修正依頼は本文下の静かなテキストボタンにし、`--signal`を使わない。
- チャプターは「この話が気になる」を実行に変える場所だ。現行どおり各行をYouTubeの`&t=`へ直リンクし、時刻を`--aqua`、ホバー時に行全体を浮かせる。詳細内で再生位置を変える仕様は作らない。
- ページの最後にも同じYouTube CTAを置く。長い要約とチャプターを読んだ後に出口を探させない。

### 3-5. マガジン一覧（`/magazine`）

```text
WEEKLY MAGAZINE
いっくん追いかけマガジン
配信とその週の出来事を、あとからたどる。

[表紙]  2026 / 09 / 21 — 09 / 27
        見出し（最大2行）
        今週の話題  タグ  タグ
        読む →
```

- 現在の単なる戻るヘッダーをやめ、ページ名と短い説明を持つ導入にする。マガジンは検索の脇役ではなく、時間をまとめて振り返る入口だ。
- リストは`divide-y`だけで流さず、`grid-cols-1 sm:grid-cols-2 lg:grid-cols-3`のカードにする。表紙の縦比率を保ち、表紙:本文をmobileで`88px : 残り`、desktopでは縦積みで表紙をカード上部に置く。
- 各カードには週の範囲、見出し、トピック最大2件、`読む →`を表示する。`content.intro`全文は一覧に出さない。
- 既存カバー画像を主役にし、カバーなしの代替は`--surface-raised`に`ICHIRO LIBRARY / YYYYMMDD`を組む。白い紙のような強い代替背景は使わない。
- クリック領域はカード全体でよい。ただし矢印とhoverで詳細へ進むことを明確にする。マガジン詳細内の配信リンク・YouTubeリンクの既存機能は維持する。

### 3-6. YouTube誘導動線（全画面共通）

| 場所 | ラベル | 遷移先 | 役割 |
|---|---|---|---|
| 一覧カード・サムネイル | `YouTube ↗` | `youtube.com/watch?v={video_id}` | すぐ観たい人の最短入口。 |
| 一覧カード・下部 | `YouTubeで開く ↗` | 同上 | カードの主アクション。文字で行き先を保証する。 |
| 一覧カード・下部 | `要点・チャプターを見る →` | `/stream/{video_id}` | 迷っている人の判断材料への二次導線。 |
| 配信詳細・タイトル直下 / 最下部 | `YouTubeでこの配信を開く ↗` | `youtube.com/watch?v={video_id}` | 詳細を読んだ人を確実に送り出す。 |
| チャプター | `時刻 + 題` | `youtube.com/watch?v={video_id}&t={start_sec}` | 興味のある瞬間から視聴を始めさせる。 |
| マガジンの配信参照 | `配信タイトル` | 現行どおり詳細 | 文脈を読んでから、詳細のCTAまたはチャプターでYouTubeへ渡す。 |

### 実装上の注意

- アイコンはUnicode（`↗`, `→`, `⌕`など）または既存CSSで済ませる。アイコンライブラリのためだけにnpm依存を増やさない。
- `StreamCard`のYouTube URLは既存の`video_id`からクライアント側で組み立てる。新しいAPIやカラムは不要。
- 画像は既存の`next/image`（カード）とカバーの既存`img`実装を維持する。今回、画像生成・差し替えは不要。
